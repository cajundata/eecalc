# eecalc v0.1 design

Date: 2026-09-16

`eecalc` is a software-only CLI for everyday electronics bench math. This spec turns README.md into an implementation contract for v0.1. It does not add features from README section 11.

Success: the five commands produce README section 4 outputs exactly, the three documented error examples match exactly, `cargo test` / `clippy` / `fmt --check` are clean, and `Cargo.toml` has zero dependencies.

## 1. Approaches considered

**A. Typed command enum, README module tree (recommended).**
`cli.rs` parses `&[String]` into a `Command` enum whose variants only represent valid input combinations. `calc/*` are pure functions. `units.rs` parses and formats values. `run()` in `lib.rs` dispatches and formats. `main.rs` prints and maps exit codes.

Trade-off: more files and types. Matches the learning objectives (enums, modules, `Result`, tests without spawning a process).

**B. Binary-only, most logic in `main.rs`.**
Faster to type, but calculation and parsing are hard to unit-test, and it ignores the `lib.rs` / `main.rs` split required by the README.

**C. Stringly-typed flag map, validate later.**
A generic `HashMap` of flags is a smaller parser, but it fights “enum variants modeling valid input combinations” and pushes correctness into ad-hoc checks.

v0.1 uses **A**.

## 2. Architecture

Crate layout matches README section 6. Cargo already names the package `eecalc` (edition 2024). Adding `src/lib.rs` makes the default lib+bin layout; no extra `[[bin]]` table is required.

```
src/main.rs          # args → run() → stdout / stderr / exit code  (~30 lines)
src/lib.rs           # modules + pub fn run(args: &[String]) -> Result<String, EecalcError>
src/cli.rs           # &[String] → Command
src/units.rs         # parse_value, format_eng
src/error.rs         # EecalcError, Display, Error, exit_code()
src/calc/mod.rs
src/calc/ohm.rs
src/calc/power.rs
src/calc/resistance.rs
src/calc/divider.rs
src/calc/rc.rs
tests/cli.rs         # spawn the built binary
```

Layering:

- `units` and `calc` know nothing about argv.
- `cli` knows flags and `parse_value`, not formulas.
- `run` knows `Command`, calc functions, and `format_eng`.
- `main` is the only I/O and process-exit site.

`run` takes `&[String]` with `argv[0]` already stripped (the values from `std::env::args().skip(1)`).

## 3. Command model

```text
Command =
    Help
  | CommandHelp(CommandName)
  | Ohm(OhmGiven)
  | Power(PowerGiven)
  | Series(Vec<f64>)        // length >= 2
  | Parallel(Vec<f64>)      // length >= 2
  | Divider { vin, r1, r2 }
  | Rc { resistance, capacitance }

OhmGiven / PowerGiven =
    VoltageCurrent { voltage, current }
  | VoltageResistance { voltage, resistance }
  | CurrentResistance { current, resistance }

CommandName = Ohm | Power | Series | Parallel | Divider | Rc
```

`cli` is the only place that counts flags and rejects the wrong number. After a successful parse, calc functions receive a valid combination.

Command names are lowercase and case-sensitive. Unknown names are `UnknownCommand`.

### Flags

| Command | Flags | Positionals |
| --- | --- | --- |
| `ohm`, `power` | `--voltage`/`-v`, `--current`/`-i`, `--resistance`/`-r`; exactly two | none |
| `series`, `parallel` | none | two or more values |
| `divider` | `--vin`, `--r1`, `--r2`; all required; no short flags | none |
| `rc` | `--resistance`/`-r`, `--capacitance`/`-c`; both required | none |

Rules:

- Flag order does not matter.
- `--flag=value` is not supported (unknown flag).
- A flag without a following token is `MissingArgument`.
- Duplicate flags, unknown flags, extra positionals on flag commands, and flags on `series`/`parallel` are `UnexpectedArgument`.
- `--help` is recognized as a token, not `-h`. `-h` is an unknown flag.
- Zero args is a usage error (exit 2), not help.
- First token `help` or `--help`: global help if it is the only token. Extra tokens after it are `UnexpectedArgument`.
- Command help: `<command> --help` only. `help ohm` is `UnexpectedArgument`.
- If the first token is a known command and any later token is `--help`, that is command help even if other flags are present.
- `ohm` / `power` with zero, one, or three of the three quantity flags is `WrongArgumentCount` (same message as the README one-flag example).

## 4. Data flow

1. `main` collects `args[1..]`, calls `run`.
2. `cli::parse` returns `Command` or `EecalcError`.
3. `run` matches:
   - `Help` / `CommandHelp` → usage string, `Ok`.
   - otherwise call the calc function, then `format_eng`.
4. `Ok(String)` is printed to stdout with a trailing newline (`println!`).
5. `Err` is printed to stderr as `error: {message}\n` and the process exits with `exit_code()`.

`rc` returns a two-line string (no trailing newline inside the string). `println!` supplies the final newline.

## 5. Units

### Input: `parse_value(&str) -> Result<f64, EecalcError>`

Scan the token in order:

1. Optional leading `+` or `-`.
2. Mantissa: digits and at most one `.` (`4.7`, `.5`, `10.` are valid). Stop at the first non-digit, non-dot character.
3. Suffix: empty, or leftover characters interpreted as the SI prefix.

No space inside the token. No exponent syntax. `1e3` is mantissa `1` plus suffix `e3`.

Reject: empty mantissa (`k`, `-k`); a second `.` (`4.7.0k`); non-finite values (`inf`, `NaN`, case-insensitive); a suffix that is not exactly one of `p n u m k M`.

Prefixes (case-sensitive):

| prefix | multiplier |
| --- | --- |
| `p` | 1e-12 |
| `n` | 1e-9 |
| `u` | 1e-6 (micro; `µ` is not accepted) |
| `m` | 1e-3 |
| (none) | 1 |
| `k` | 1e3 |
| `M` | 1e6 |

Mantissa: `str::parse::<f64>` on the numeric slice. Allow `.5` and `10.`. Reject empty mantissa (`k`, `-k`), more than one `.`, and any leftover other than one known prefix.

`10x` → `InvalidNumber` displaying exactly: `invalid value '10x': unknown SI prefix 'x'`.

Other bad tokens use `invalid value '{token}': {reason}` (`not a number`, `unknown SI prefix '{p}'`).

### Output: `format_eng(value: f64, unit: &str) -> String`

- Four significant figures, then strip trailing zeros and a dangling decimal point.
- Prefix chosen from `p n u m (none) k M` so the absolute mantissa is in `[1, 1000)` when possible.
- If the value is outside that range, use the edge prefix (`p` or `M`) even if the mantissa falls outside `[1, 1000)`. Do not invent `G` or scientific notation.
- Zero: `0` plus a space plus the unit, no prefix (`0 V`).
- Sign is preserved; prefix is selected from the absolute value.
- One space between mantissa and prefix+unit (`25.53 mA`, `6.6 V`, `650 Ω`).
- Micro on output uses `u`, not `µ`.
- After rounding, if the mantissa reaches `1000`, roll to the next prefix. If already `M`, leave mantissa at `1000` or larger.

Units passed in: `V`, `A`, `Ω`, `W`, `s`, `Hz`.

## 6. Calculations

All calc functions are pure, take `f64` / small enums / `&[f64]`, return `Result<_, EecalcError>`, and carry doc comments with the formula.

Resistance and capacitance must be `> 0` (`NonPositiveValue`). Voltage and current may be zero or negative. Computing `R = V / I` with `I == 0` is `DivisionByZero`. `I = 0 / R` is valid (`0 A`).

| Command | Function | Formula | Printed form |
| --- | --- | --- | --- |
| `ohm` | `ohm(OhmGiven)` | `V=IR`, `I=V/R`, `R=V/I` | `V = …` / `I = …` / `R = …` |
| `power` | `power(PowerGiven)` | `P=VI`, `P=I²R`, `P=V²/R` | `P = …` |
| `series` | `series(&[f64])` | `Σ Rn` | `R = …` |
| `parallel` | `parallel(&[f64])` | `1 / Σ(1/Rn)` | `R = …` |
| `divider` | `divider(vin, r1, r2)` | `Vin * R2 / (R1+R2)` | `Vout = …` |
| `rc` | `rc(r, c)` | `tau=R*C`, `fc=1/(2πRC)` | see below |

`rc` stdout (spaces are significant):

```text
tau = 10 ms
fc  = 15.92 Hz
```

`fc` is padded so `=` aligns with `tau =`.

README section 4 success lines are golden tests, including spacing and the `Ω` character.

## 7. Errors

One enum in `error.rs`. Variants are exactly:

- `UnknownCommand(String)`
- `MissingArgument(String)`
- `UnexpectedArgument(String)`
- `InvalidNumber { value: String, message: String }`
- `WrongArgumentCount { command: &'static str }`
- `NonPositiveValue { what: &'static str }`
- `DivisionByZero`

`Display` is the message **without** the `error: ` prefix. `main` prints `error: {e}`.

`std::error::Error` is implemented. No `panic!` / `unwrap` / `expect` in library code.

Exit codes:

| Group | Code |
| --- | --- |
| success, including help | 0 |
| `NonPositiveValue`, `DivisionByZero` | 1 |
| all other `EecalcError` variants | 2 |

### Locked messages (README section 4)

- `ohm` with the wrong number of quantity flags: `ohm requires exactly two of --voltage, --current, --resistance` (`WrongArgumentCount`, exit 2).
- `power` with the wrong number of quantity flags: `power requires exactly two of --voltage, --current, --resistance` (`WrongArgumentCount`, exit 2).
- `--resistance 0`: `resistance must be greater than zero` (`NonPositiveValue { what: "resistance" }`, exit 1). Capacitance uses `capacitance must be greater than zero`.
- `10x`: `invalid value '10x': unknown SI prefix 'x'` (exit 2). `1e3` displays `unknown SI prefix 'e3'`.

### Remaining messages (same `error: …` style)

- Unknown command: `unknown command '{name}'`
- Missing flag value: `missing value for {flag}`
- Unexpected extra / duplicate / unknown flag / bad positional: `unexpected argument '{token}'`
- `series`/`parallel` with fewer than two values: `{command} requires at least two values`
- `divider` missing a required flag: `divider requires --vin, --r1, and --r2` (`MissingArgument`)
- `rc` missing a required flag: `rc requires --resistance and --capacitance` (`MissingArgument`)
- Zero current when computing resistance: `current must not be zero`
- Zero args: `missing command` (`MissingArgument`)

## 8. Help text

`eecalc help` and `eecalc --help` print:

```text
eecalc - electronics bench calculator

Usage:
  eecalc <command> [arguments]
  eecalc help | --help
  eecalc <command> --help

Commands:
  ohm       Given any two of voltage, current, resistance, compute the third
  power     Given any two of voltage, current, resistance, compute power
  series    Equivalent resistance of two or more series resistors
  parallel  Equivalent resistance of two or more parallel resistors
  divider   Output voltage of a two-resistor divider
  rc        Time constant and cutoff frequency of an RC circuit

Values:
  A decimal number with an optional SI prefix from p n u m k M.
  Examples: 470, 4.7k, 100n, 2.2M
  No space between number and prefix. u means micro.

Exit codes:
  0  success
  1  calculation error
  2  usage or parse error
```

`<command> --help` prints the block for that command. Each block starts with `Usage:` and ends with the same two-line value-syntax note: `Values: decimal plus optional prefix p n u m k M (u = micro). Examples: 470, 4.7k, 100n.`

```text
Usage: eecalc ohm --voltage <V> --current <I> --resistance <R>
  Give exactly two of --voltage/-v, --current/-i, --resistance/-r.

Usage: eecalc power --voltage <V> --current <I> --resistance <R>
  Give exactly two of --voltage/-v, --current/-i, --resistance/-r.
  Prints power P.

Usage: eecalc series <R1> <R2> [R3 ...]
  Two or more resistances. Prints equivalent R.

Usage: eecalc parallel <R1> <R2> [R3 ...]
  Two or more resistances. Prints equivalent R.

Usage: eecalc divider --vin <V> --r1 <R> --r2 <R>
  All three flags required. Prints Vout.

Usage: eecalc rc --resistance <R> --capacitance <C>
  Both --resistance/-r and --capacitance/-c required. Prints tau and fc.
```

For `eecalc ohm --help`, stdout is the ohm `Usage:` block, a blank line, then the shared `Values:` line. Same pattern for the other commands. Unit tests compare those strings exactly.

## 9. Testing

Relative tolerance helper: `|a-b| <= 1e-9 * max(1, |a|, |b|)` so zeros still compare.

- `calc/*.rs`: hand-checked cases per formula, including a negative voltage/current for `ohm` and a `DivisionByZero` on `R=V/I`.
- `units.rs`: every prefix, plain decimals, signs, `.5`, `10.`, and at least the malformed inputs `10x`, `k`, `10kk`, `1e3`, `10µ`, empty string, `4.7.0k`, `inf`.
- `cli.rs`: each command’s valid form; each error variant that command can produce; help; flag order; shorts.
- `tests/cli.rs`: spawn `CARGO_BIN_EXE_eecalc`; at least one success and one failure per command; assert stdout, stderr, exit code. Include every README section 4 example as a golden case. stdout is UTF-8 (`Ω`).

`cargo test` has zero warnings. `cargo clippy` on default lints is clean. `cargo fmt --check` is clean.

## 10. Out of scope (unchanged from README)

`clap`, `assert_cmd`, REPL, GUI, `=value` flags, `-h`, `help <command>`, SI prefixes outside `p n u m k M`, `µ`, exponent input, E-series rounding, AC/impedance, colored output, shell completions, `no_std`.

## 11. Decision log

Decisions below were taken as recommendations after the user chose README-faithful v0.1 and asked remaining questions to be decided, not asked.

1. Build README v0.1 only: five commands, hand-rolled CLI, zero crates.
2. Section 4 success outputs are exact golden strings.
3. The three section 4 error examples are exact; other errors follow the `error: …` style defined in this spec.
4. Architecture is approach A (typed `Command` enum, README module tree).
5. Keep Cargo edition 2024 and package name `eecalc`.
6. `run(&[String])` with program name already stripped.
7. Help is `Ok(String)`, not an error; exit 0.
8. No-args is a usage error (exit 2), not help.
9. `--help` only; no `-h`. `<command> --help` only; no `help <command>`.
10. `--flag=value` is not supported.
11. Divider has no short flags.
12. SI prefixes are exactly `p n u m k M`, case-sensitive; `u` is micro.
13. No scientific-notation input.
14. Output micro uses `u`. Out-of-range magnitudes use edge prefixes `p` or `M`, never `G` or `1e9` style.
15. `EecalcError` has the seven README-suggested variants; duplicates/unknown flags fold into `UnexpectedArgument`.
16. `Display` does not include `error: `; `main` adds it.
17. Resistance/capacitance `> 0`; voltage/current may be zero or negative; `I=0` when computing `R` is division by zero.
18. `rc` `fc` line uses two spaces before `=` so columns align.
19. Integration tests use `std::process::Command`, not `assert_cmd`.
20. Library code has no `unwrap`/`expect`/`panic!`.
21. Extra tokens after global `help`/`--help` are errors, not ignored.
22. `ohm`/`power` with 0, 1, or 3 quantity flags share the README “exactly two” message.
23. Reject `inf` / `NaN` inputs as invalid numbers.
24. Command-help strings in section 8 are exact golden strings.
